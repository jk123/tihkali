Note on clause 3: the ad-material clause is why the acknowledgement at the
top of this file exists. It is also why the resolver was NOT vendored --
NetBSD's lib/libc/resolv/res_send.c is 3-clause and pulls a userspace
socket layer we do not have.

Why this file is vendored rather than transcribed by hand: it is the
authoritative source for NetBSD syscall numbering, including the compat_09
through compat_110 layers. Re-deriving those numbers by hand is how the
wrong number silently ends up dispatched.


Generated code
--------------

kernel/build.rs parses syscalls.master at build time and emits
$SYSNAME constants. The generated Rust carries the NetBSD CVS id
(syscalls.master,v 1.316) in a doc comment on each constant block so the
provenance of every number stays traceable to its upstream revision.
